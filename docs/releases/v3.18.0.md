## 版本说明

一条判据分层补充：**同一个签名参数，在不同接口上的校验强度可能完全不同**。新增案例记录「参数存在性门禁」与「内容校验 + 验证中心凭证」两种强度的区分方法，以及一次把「参数缺失 / 会话过期」误判成「环境指纹不符」的高代价纠偏。

## 主要变更

- **新增案例 `cases/presence-gate-vs-verify-center-credential.md`**：
  - 同一服务两条接口共用同一套前端 SDK、同一个签名参数，但一条**只校验该参数是否存在**（随机值、甚至空值都能过），另一条**校验签名真伪**并额外要求一个验证中心签发的凭证参数（其值等于某条 Cookie）。
  - 记录「算法产物」与「凭证」的区分方法：伪造同格式值仍被拒 → 该参数是服务端认识的具体值，不是可自行计算的产物；凭证通常**跨会话、跨 UA、跨请求参数**复用，而会话 id 可以随手新建。
  - 记录签名与**完整 query 串**绑定的判定方式：SDK 会自动追加若干参数再签名，因此必须签「最终要发出去的那个串」，不能签完再改。
  - 记录 **mock / route 拦截取"未消费签名"** 的手法：把请求挡在出网之前，页面照常签名，于是能拿到一个未被服务端消费的值，用来充当控制组或参数模板。
- **纠偏（本版最重要的可复用经验）**：两次把失败归因为「运行环境指纹不符」，真实原因是①签名串缺少必需参数、②控制组用了过期会话（其重放本身就是拒绝）。案例里完整保留了「当时的假设 / 推翻它的证据 / 现在的结论」三段，并写明**控制组失效时停止归因**这条纪律的实际代价。
- **`SKILL.md` 更新记录**新增一行，指向上述判据分层，不写入站点细节（站点词仍只允许出现在 `cases/`）。
