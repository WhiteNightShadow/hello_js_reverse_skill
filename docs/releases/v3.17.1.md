## 版本说明

v3.17.1 在问题路由中补齐响应诊断显式度与页面控制组先验分流规则，同步配套 `camoufox-reverse-mcp v1.13.1` 的超长 URL 预览截断标记契约，新增同实体多入口判据分离脱敏案例，并修复中文 Windows（GBK 默认编码）下测试与脚本的 UTF-8 读写兼容问题。

## 主要变更

- **响应诊断显式度与控制组先验分流（`references/problem-routing.md`、`SKILL.md`）**：
  - 区分**明示前置缺口**（业务码或文案直接指出未登录、无权限、参数缺失、地区受限等 → 先补齐条件或如实记录外部依赖，不进入签名逆向）与**静默/模糊拒绝**（通用模糊错误码、`HTTP 200 + 0 字节`、或仅含空壳字段的 JSON → 多因同象，单看响应不定层）；
  - 严格衔接第 2 步页面控制组判据：当真实浏览器控制组自身也返回 `0` 字节或风险提示时立即停止签名归因，优先核查登录态并横向对比同业务实体的其他官方入口（比较闸门重量与报错显式度，采用前核验 S3 字段完整度且不反向套用 `R0` 结论）；仅当控制组稳定到达 S3 而本地失败时，才进入 `A / A2 / B` 来源替换与传输/伴生头消融。
- **同步 MCP v1.13.1 工具契约与证据边界（`references/mcp-tools.json`、`references/mcp-tool-reference.md`、`references/browser-evidence-contract.md`）**：`list_network_requests` 与 `wait_for(mode="request"|"auto")` 请求摘要超过 200 字符时以 `…` 结尾并置 `url_truncated` / `url_length`；明确严禁凭截断预览判定查询参数或签名缺失，核对前须调用 `get_network_request(request_id=...)` 获取完整 URL。
- **通用脱敏案例与文档门禁加固（`cases/multi-entry-surface-triage-and-diagnostic-specificity.md`、`tests/test_skill_docs.py`）**：沉淀同实体多入口闸门分离、跨域匿名票据握手隔离与超长 URL 预览截断纠偏案例；新增非历史遗留案例强制脱敏标签门禁与站点词表扩充。
- **中文 Windows（GBK）UTF-8 编码兼容（`tests/`、`scripts/real_cases/`）**：显式为子进程管道（`subprocess.run` / `check_output`）与文件读写指定 `encoding="utf-8"`，消除中文 Windows 默认 `cp936` 下的 `UnicodeDecodeError`。

## 兼容性

- 入口行数预算（`SKILL.md < 220` 行）、模板目录与既有工作流不变；`url_truncated` / `url_length` 字段需配套 `camoufox-reverse-mcp >= 1.13.1`，旧版仍可正常调用。

## 验证

- `python3 -m unittest discover -s tests -v` 全量通过（含站点词隔离、非历史案例强制脱敏门禁、相对链接与锚点解析、脚本与模板回归）。
- `scripts/check-mcp-contract.py --mcp-root ../camoufox-reverse-mcp` 快照一致性校验通过。
