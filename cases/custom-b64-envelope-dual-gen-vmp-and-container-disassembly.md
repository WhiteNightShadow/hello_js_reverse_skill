# 自定义换表 Base64 信封、双代 JSVMP 前缀判读与字节码容器拆解

> 难度：★★★★
> 还原方案：R3 + R0 混合（`jsdom` 最小宿主容错离线运行原始 JSVMP 实体 + 黑盒探针提取 64 项自定义 Base64 字母表 + 剔除冗余遥测头）
> 实现语言：Node.js（`jsdom` 离线出值）+ Python（组包与 TLS 客户端发送）
> 最后验证日期：2026-11-23
> 平台类型：通用（已脱敏）
> 适用范围：授权测试目标上的内容流查询接口；仅验证单目标当前前端构建版本（含两套地域静态资源变体）当天样本
> 到达层级：S3（纯离线生成内层 JSVMP 令牌与外层换表 Base64 信封，多组请求稳定返回 HTTP 200 与完整业务列表）；S4 跨天换代未验证
> 失效条件：外层换表 Base64 字母表轮换、旧代字节码程序停收或持久设备指纹串结构规则变更

本案例已移除全部站点域名、应用标识、构建号、静态包哈希、SDK 与函数名、请求头名、Cookie 名、本地存储键名、真实 64 字符自定义字母表、容器魔数字面量及业务错误码编号，仅保留自定义 Base64 黑盒探针提表、三层失败状态分层归因、双代 JSVMP 前缀判读、二进制字节码容器结构拆解及 `jsdom` 离线运行时的通用定位方法。结论仅对当时的受控测试样本成立，不是全局规则。

## 背景

目标业务接口在请求头中携带三项安全相关参数：带固定版本前缀的外层动态签名头、毫秒级时间戳头、同套自定义字母表编码的会话级公共设备信封头，页面自发请求还会附带另一枚风控遥测头。业务打包脚本仅负责拼装外层信封并计算请求路径与正文摘要，真正的内层核心令牌由异步接口按模块类型下发的动态脚本（`fetch` + `eval` 形态，无 `<script src>` 资源）在虚拟机解释器中生成。

排查初期同时遇到四重混淆现象：
1. **同一份有效签名在不同客户端表现截然不同**：普通 HTTP 客户端（Node `undici` / 标准 `curl`）一律返回网关拦截状态码与 `{"code":0,"data":{}}` 空壳响应，容易误判为签名算法错误；
2. **内层令牌出现两套固定前缀与两档长度**：不同批次下发的模块分别产出外层带 Base64 `=` 填充的较短令牌（解码 92 字节，`92 % 3 == 2` 且 `92 % 16 == 12`）与无填充、16 字节整块对齐的较长令牌（解码 144 字节，`144 % 16 == 0`），直观上酷似“环境降级评分”；
3. **空种子下静默产出退化短串**：当 `localStorage` 中的持久设备指纹串缺失时，JSVMP 入口不报错，仍返回带合法版本前缀的 9 字符退化串，但服务端必然拒绝；
4. **多个动态模块覆盖同一全局槽**：页面按序加载指纹模块与签名模块时复用同一个全局属性暂存二进制字节码容器，事后读取只能拿到最后加载模块覆盖后的容器。

## 走过的链路

1. **先用固定有效签名做跨客户端与单头摘除对照，切开三层失败码**。拿到浏览器内刚生成且未消费的一套请求头后，先不在本地改任何 JS 代码，直接在标准 HTTP 客户端与浏览器级 TLS 模拟客户端之间做同参对照（见 [协议层分析与对抗](../references/protocol-analysis.md)）：确认标准客户端的空壳拦截完全由 TLS 指纹门触发；切到匹配浏览器指纹的客户端后，逐一摘除各自定义头——缺少公共设备信封触发空壳拦截码，缺少动态签名触发显式拒绝码，而去掉附加遥测头仍返回完整数据（按 `R0` 直接不发）；同时确认境外出口触发跨地域构建重定向时会导致会话信封与目标域不匹配而报内部负数业务码，不再与签名错误混为一谈。
2. **用 `[i << 2, 0, 0]` 探针扫出自定义 Base64 表，先证伪外层加密假设**。观察到外层签名去掉固定前缀后长度恒为 4 的倍数且仅含 64 种字符，直接在页面/沙箱对编码函数循环喂入 64 组 3 字节数组 `[i << 2, 0, 0]`（`i = 0..63`），取每次返回字符串的第 1 个字符拼成 64 字符表（见 [不透明令牌分析](../references/opaque-token-analysis.md)）。用该表解码抓包样本即直接得到明文 JSON，确认外层仅封装协议版本、端标识、系统名、`md5(path + body)` 摘要以及内层 JSVMP 产出的核心子令牌。
3. **用 setter 序列捕获全部字节码容器，拆解容器格式并证伪“环境评级前缀”假设**。动态脚本经异步 JSON 接口下发（可用 `extract_script` 直接按 JSON 路径提取落盘，见 [混淆识别与还原指南](../references/obfuscation-guide.md)），多个模块加载时依次向同一全局属性写入二进制容器。通过在加载前用 `Object.defineProperty` 为该属性安装 `setter` 把每次写入按序保存，完整拿到签名模块与指纹模块各自的容器并完成二进制结构拆解：
   - **容器头部结构**：固定魔数前缀 + 隐写在头部特定字节（如 `byte[12..15]`）低 2 位中的掩码键 + 大端无符号 32 位代码段长度（`u32BE`）+ 变长前缀码编码的常量池；
   - **同解释器异程序 vs 异代指令集判定**：对照反汇编指令边界是否精确落位及前缀码常量池词组重合度，区分“同一 VM 下的签名程序与指纹程序”以及“新旧两代字节码”；
   - **代次证伪实验**：在调用期人为清空画布、音频、`getComputedStyle` 等环境接口输出，内层令牌前缀始终保持不变，证实两套前缀对应服务端并存下发的两代字节码程序（解码长度 92B vs 144B），且干净会话下两代均被服务端正常接受。
4. **最小化 `jsdom` 宿主修补并补齐 S1 退化短串断言**。将提取出的原始动态实体放入锁定同基线 Firefox UA 的断网 `jsdom` 执行（见 [原始 SDK 运行](../references/original-sdk-runtime.md)）：
   - 极简 `<html></html>` 文档骨架因缺少页面挂载节点使上游节点查找返回 `undefined`，进而在 `appendChild` / `removeChild` / `insertBefore` / `replaceChild` 处抛出未捕获的 WebIDL `TypeError`（真实浏览器传入 `undefined` 同样抛错，因页面节点存在才未触发）；在核实当前样本不做负向 WebIDL 抛错校验与 `Node.prototype` `toString` 检查后，仅在外层包一层保留正常 `Node` 行为的异常兜底，且**不对 `window` 使用泛化 `Proxy`**（避免 `get` / `has` 破坏 `typeof`、`in` 与真值分支），仅精确挂载其点名调用的无参宿主回调；
   - 注入会话内采集的真实持久设备串，并在 S1 校验中强制断言子令牌长度区间（如 ≥120 字符）与换表解码字节数，拦截持久设备串缺失时静默产出的 9 字符退化废值。

## 可复用的排查模板（已脱敏）

```javascript
// 1. 黑盒恢复 64 项自定义 Base64 字母表（对剥离外层固定前缀后的底层字节数组编码入口探测）
function recoverCustomB64Alphabet(encodeBytesFn) {
  let alphabet = "";
  for (let i = 0; i < 64; i++) {
    const out = encodeBytesFn([i << 2, 0, 0]);
    alphabet += out[0];
  }
  if (new Set(alphabet).size !== 64) {
    throw new Error(`Expected 64 unique chars, got ${new Set(alphabet).size}`);
  }
  const padSample = encodeBytesFn([0]);
  const padChar = padSample.length === 4 ? padSample[3] : null;
  return { alphabet, padChar };
}

// 2. 仅在独立观察会话使用：捕获被后续动态模块覆盖的全局容器写入序列（首个模块执行前安装）
function captureOverwrittenGlobalWrites(win, propName) {
  const writes = [];
  const snapshot = val =>
    ArrayBuffer.isView(val)
      ? new Uint8Array(val.buffer.slice(val.byteOffset, val.byteOffset + val.byteLength))
      : val instanceof ArrayBuffer
        ? val.slice(0)
        : Array.isArray(val)
          ? val.slice()
          : val;
  const hadOwn = Object.prototype.hasOwnProperty.call(win, propName);
  let current = hadOwn ? win[propName] : undefined;
  if (hadOwn) {
    writes.push(snapshot(current));
  }
  Object.defineProperty(win, propName, {
    configurable: true,
    enumerable: hadOwn,
    get() {
      return current;
    },
    set(val) {
      writes.push(snapshot(val));
      current = val;
    },
  });
  return writes;
}
```

## 踩坑与纠偏

- **不要跳过传输层对照直接怀疑签名算法**：同一枚新鲜有效签名在普通 HTTP 库稳定返回空壳拦截、在浏览器 TLS 指纹客户端立即通过，花几分钟做一次同参通道对照即可省掉数小时无效的 JS 逆向。
- **不要把“函数不报错且返回带前缀字符串”当成 S1 通过**：持久设备指纹串为空时，JSVMP 仍会返回 9 字符退化串而不抛任何异常；S1 必须同时校验长度下限、前缀与外层/内层解码后的结构完整性。
- **不要给 `window` 套全局 `Proxy` 充当万能空函数桩**：ECMAScript `Proxy` 的 `get` 陷阱无法区分函数调用与 `typeof`、真值判断或 `instanceof`（单拦 `get` 还会与 `in` 操作符触发的 `has` 陷阱不一致），在共享成员解引用辅助函数的虚拟机中会把本应为 `undefined` 的环境检测项全部变成真值函数而提前走入异常分支。
- **不要把短窗频控误判为令牌一次性作废**：连续无间隔请求触发风控码后，先做冷却复发实验（等待冷却窗口后重发同一枚令牌），确认可复用后只需收敛请求速率，无需每次重建会话。
