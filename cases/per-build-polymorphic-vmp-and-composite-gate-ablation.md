# 按会话重编译多态 JSVMP、运行期窗口自证提密钥与联合门禁金标准消融

> 难度：★★★★★
> 还原方案：R3 + R1 混合（本地沙箱运行当次 SDK 采集载荷 + 运行期窗口自证提取当次分组密钥 + 金标准成组二分消融定位联合校验槽）
> 实现语言：Node.js / Python
> 最后验证日期：2026-11-20
> 平台类型：通用（已脱敏）
> 适用范围：授权测试目标上的动态网关预检—环境遥测令牌提交—业务放行链路；仅验证单目标当前网关版本短批次
> 到达层级：S3（遥测令牌交换通过 + 后续业务接口返回有效数据）；未到 S4
> 失效条件：网关更换外层分组密码或填充方案、新增服务端联合评分槽位、调整会话上下文绑定规则或出口限流策略

本案例已剥离全部厂商名称、站点域名、脚本文件名、接口路径、请求头与参数名、单版本密码学常数及具体槽位编号，仅保留跨体系通用的多态字节码观测方法、运行期密钥自证提取、跨引擎 `Error.stack` 副作用排查与联合门禁反向消融纪律。结论仅对当时的受控测试样本成立，不是全局规则。

## 背景

目标网关在业务请求前执行两段式会话预检：预检接口下发一次性会话标识与动态脚本地址（URL 携带每次变化的随机载荷参数）；客户端加载该脚本采集运行环境遥测信息，组装为上百个字段的分隔符结构化明文，在虚拟机内部经对称分组密码加密并编码后提交至令牌交换接口。

该目标同时叠加了三层分析阻力：
1. **按请求重编译的多态 JSVMP**：连续拉取十余次脚本，每次返回的字节 `sha256`、源码列偏移与内部 `switch-case` 的 opcode 编号均不相同，且虚拟机采用非扁平化寄存器数组分发结构（常规阶段插桩 `tap_stage_calls` 命中数为 0）。
2. **内嵌于当次随机字节码的会话密钥**：分组密码密钥既不在网络接口 JSON 中明文下发，也不以源码数组字面量存在，而是在当次字节码执行期动态拼入寄存器阵列。
3. **服务端多槽联合评分门禁**：本地 Node `vm` 跑出的明文载荷与真实浏览器基线存在数十处差异，每次单独修正其中一处，服务端均返回完全相同的拒绝响应，单向逐项试错无法获得正向梯度。

## 走过的链路

1. **用与 opcode 编号脱钩的结构正则建立跨构建观测**。面对每次刷新都重排 opcode 编号的单行多态脚本，放弃搜固定 `case 0xNN:`，转而提取虚拟机向寄存器槽位写入时的语法骨架正则：
   - 在线批量观测时，用 `instrumentation(action="install", mode="regex", inject=[...])` 对匹配写口前注入带内联计数门控的轻量探针（经过字面量跳过、`case` 标签冒号后移与现代语法解析校验）；需要反复修改大体积探针脚本时，用 `intercept_request(..., mock_response={"body_file": ...})` 从磁盘按请求重读；
   - 需要暂停查看闭包与寄存器上下文时，用 `rdp_debugger(action="set_breakpoint", url_pattern=..., find=...)` 下正则断点，`reload` 获取新构建后由调试器自动重算 UTF-16 行列并吸附重挂（详见 [源码级插桩指南](../references/jsvmp-source-instrumentation.md) 与 [浏览器取证契约](../references/browser-evidence-contract.md)）。
2. **运行期定长窗口采样 + 同次密文结构自证提取当次密钥**。由于该无预展开密钥编排的分组密码每轮运算都会高频读取 4 个 32 位轮密钥字，在本地受控 `vm` 执行当次脚本出值时，对虚拟机整数寄存器阵列中的连续定长无符号 32 位窗口记录读取频次并降序取前若干候选窗口，直接对同次产出的密文做离线试解密：筛出解出字节流同时满足外层 JSON/分隔符语法合法、可打印 ASCII 占比与字段总数恒定的当次密钥，在不依赖任何静态字节码偏移的前提下完成 `decode(encode(x)) == x` 闭环（详见 [不透明令牌分析](../references/opaque-token-analysis.md)）。
3. **排查跨引擎 `Error.stack` 正则解析引发的静默异常写槽**。解密对比明文槽位后发现，某处本应记录脚本URL与执行耗时的槽位在本地变成了固定错误标识。追踪发现 SDK 内部构造 `new Error().stack` 并用适配 Firefox/SpiderMonkey 格式（`fn@url:line:col`）的正则提取调用栈来源；在 Node.js（V8）中默认栈首行为 `"Error"` 且帧格式为 `"    at fn (filename:line:col)"`，正则匹配返回 `null` 后紧接着取下标抛 `TypeError`，被 SDK 外层 `try/catch` 吞掉并转写为异常遥测值。为 `new vm.Script(code, { filename: scriptUrl })` 指定真实脚本 URL，并通过非枚举 `Error.prepareStackTrace` 过滤宿主帧后输出与基线一致的栈文本，该槽位即恢复正常（代码模式见 [jsdom 环境补丁](../references/jsdom-env-patches.md)）。
4. **守住基线实测等价性，拒绝无证据的“更真”替换**。排查过程中曾怀疑本地轻量 Canvas 存根过于简陋，尝试替换为第三方原生渲染绑定库绘出真实图形像素，结果画布摘要槽反而偏离基线——核对真实 Camoufox 基线样本发现，基线浏览器在抗指纹保护下自身的画布读回本就返回全零像素摘要，原轻量存根与基线完全一致。立刻撤回第三方渲染依赖。
5. **先过 Step 0 金标准往返自证，再用成组二分消融拆开联合评分门禁**。面对剩余数十个本地与浏览器不一致的槽位，单改任一槽位均不翻转服务端判决：
   - **Step 0（排除脚手架自身破坏）**：在浏览器发送前截断取得一份未消费的新鲜真机样本（或将非会话遥测槽移植到新预检会话），离线解密为明文后**一字不改**重新序列化、重加密并随对应会话上下文提交。首次实验竟然被拒——立刻定位到测试发包脚本在提交时把明文内部绑定的原会话标识覆盖成了另一份新预检会话标识；修正脚手架保持成套会话上下文后，原样重打包稳定通过，证实加解密层与发送通道无损。
   - **成组折半反向消融**：以未消费的真机明文为金标准底座，将本地差异槽位成批换入观察判决是否翻转为拒绝（换入某半后仍通过则暂缓修补，先对翻转为拒绝的另一半继续折半细分；若后续正向验收仍差阈值，再固定已修项对其余差异槽补做折半剥离）。仅用十余次在线预算即从上百个槽位中锁定服务端联合评分实际敏感的极少数槽位（会话标识成套绑定、自动化环境标志、顶层/嵌入帧窗口关系及单调交互计数）。
6. **正向闭环验证**。回到本地沙箱生成链路，仅针对上述有服务端校验正证据的缺口补齐对应环境语义与会话参数传递，不再堆砌无关补丁，在预算内稳定通过令牌交换与后续业务请求（S3）。

## 假设与纠偏

| 当时的假设 | 推翻它的证据 | 现在的结论 |
|---|---|---|
| 可以先找出关键 opcode 编号再写死插桩规则 | 同一会话连续刷新拉取的脚本字节哈希与 `case` 编号每次全变 | 对按请求重编译的多态 VM，插桩与断点定位应绑定语法结构正则而非单次构建的编号或偏移 |
| 会话密钥既然每次都变，只能在字节码固定偏移硬抠 | 字节码偏移随每次重编译漂移，但轮函数对 4×32-bit 密钥窗口的高频读取特征恒定，且可用同次密文离线自证 | 动态编译场景优先用「运行期读频窗口候选 + 同次密文结构自证」替代静态偏移提取 |
| SDK 没有向外抛错就说明本地沙箱没有运行时异常 | 解密明文槽位发现内部 `try/catch` 把 V8 `Error.stack` 正则失配引发的 `TypeError` 记成了异常特征值 | 当基线 UA 为非 V8 内核且 SDK 采集调用栈时，核对 `vm.Script` 的 `filename` 与 `Error.stack` 文本格式 |
| 把空壳 Canvas 换成能画图的原生库更接近真机 | 基线浏览器在隐私/抗指纹配置下自身就返回全零像素，换上真实渲染反而制造差异 | 补环境只以当前基线浏览器的实测输出为准，不凭主观印象替换已对齐项 |
| 改了某槽服务端依然拒绝，说明该槽不被服务端校验 | 服务端对多槽做联合评分，单修 1 槽不足以跨过通过阈值；改用金标准反向折半消融后证实该槽属于核心校验集合 | 单向正向修补无梯度时，只要密文可往返重打包，切换为「Step 0 自证 + 金标准成组反向消融」（见 [对照实验](../references/controlled-experiments.md)） |

## 可以带走的和带不走的

可以带走的是四条跨体系通用方法：
1. **结构正则优先于单构建编号**：脚本每次下发重排 opcode 与偏移时，用源码级结构正则插桩（`inject`）与正则断点（`url_pattern` + `find`）维持跨刷新可观测性。
2. **用同次密文结构不变量做离线密钥自证**：对称分组密钥藏在多态字节码中时，利用轮函数窗口读频收敛候选集，再用明文结构合法性做零网络消耗的自证筛选。
3. **跨内核运行原始 SDK 时检查 `Error.stack` 格式与内部静默 `try/catch`**：V8 与 SpiderMonkey/WebKit 的栈帧文本差异不仅影响环境指纹，还会让解析栈字符串的正则抛空指针异常并污染载荷。
4. **联合门禁先过 Step 0 再做金标准折半消融**：原样解包重打包未跑通前不进入槽位归因；跑通后用对半退化法在对数级请求预算内剥离无关差异槽。

带不走的是任何单目标细节：特定分组密码轮数或常数、具体分隔符、总槽位数、被校验槽位的下标、特定自动化探测表达式或特定网关返回码。不同目标或同目标换版后，需重新过 Step 0 往返自证并重跑成组消融。
