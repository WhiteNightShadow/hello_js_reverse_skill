# 同平台多端 SDK：来源隔离、状态回放与结论纠偏

> 难度：★★★★★
> 还原方案：按端分别选择，见下表
> 实现语言：Python，原始 SDK 在浏览器级运行时中执行
> 最后验证日期：2026-11-05
> 平台类型：通用（已脱敏）
> 适用范围：一次为期数周的跟踪，涉及一个平台的三个 Web 端；每端只验收了单个目标
> 到达层级：各端 S3（单条）；未到 S4
> 失效条件：SDK 换版，或服务端收紧校验

本案例已去掉站点、接口、参数名和具体数值，展示方法在一个真实目标上怎么走，以及哪些判断被推翻过。结论只对当时的目标成立，不是全局规则。

## 背景

同一平台的三个端（A、B、C）都要取商品详情，共用一个 SDK 家族，但版本不同。签名头 S 是长令牌，外层有自定义编码、校验位、魔数和长度字段，内层被按请求变化的掩码盖住。另有会话令牌 Z 和随机头 D。拒绝表现为 HTTP 200 内的业务错误码。

## 问题定位记录

三个端的闸门、所需状态和路线都不同，这是本案例最重要的一点：

| 端 | 现象 | 失败层 | 路线 | 外部依赖 |
|---|---|---|---|---|
| A | 额外发送 S 反而被拒 | 请求形态 | R0（不发 S），本地 SDK 只出 Z | 浏览器提供会话 |
| B | 静态或复用的 S 被拒，服务端在 SDK 未换版时收紧 | 动态值 | R4，最小状态即可 | 浏览器提供会话和模板 |
| C | 新鲜的本地 S 仍被拒，真实页面的 S 通过 | 运行环境 | R4，完整状态回放 | 浏览器提供快照、模板和非 S 头 |

## 走过的链路

1. **先用真实页面定基线**。让页面生成未使用的 S，本地 HTTP 发送，到 S3。这一步同时证明了本地传输可用，排除了一个大方向。
2. **来源替换**。A 组完整真实请求、A2 组冻结其余字段换新的真实 S、B 组换本地 S。A、A2 成功而 B 失败，把问题定到本地值。
3. **隔离时序**。三次都用新真实 S、冻结其余字段全部成功，又用全新模板首用本地 S 仍失败，排除了“冻结”和“第三次复用”是必要原因。
4. **进入 SDK 内部**。跟踪实际读值，发现窗口几何、焦点、DOM 命中、性能条目确实被读取且与基线不同；哨兵实验确认部分值首次读取后缓存；多入口的中间值逐字一致，所以换入口没有意义。
5. **组合回放**。原生 Cookie 属性、Storage 语义、几何、完整性能条目、用原始 URL 加载、先 seed 后 init、前后状态检查，到 S3。
6. **诚实收口**。这次同时换了 SDK 版本和多项环境，所以写“组合成立”，不归因到某一项。

## 假设与纠偏

| 当时的假设 | 推翻它的证据 | 现在的结论 |
|---|---|---|
| 复制页面的头到本地失败，是服务端校验连接层指纹 | 未使用的 S 走同一个本地客户端成功 | 失败来自值已用过，不是传输 |
| 静态值全部对齐仍被拒，是“真实性硬墙” | 该接口删掉 S 后直接成功 | 绕开问题比攻克它便宜，“硬墙”是错的 |
| 负对照“只变了 S” | 回读脚本发现 D 每组重新生成，负对照还复用了前一组已发送的字段 | 只能支持新鲜度方向，不构成证明 |
| 实验失败说明本地 S 不行 | 实验跨过了验证证书的到期点 | 这次结果无效，补了发送前门禁 |
| 控制组失败时候选也算失败 | 恢复后控制组成功，候选当时根本没执行 | 控制组失效的批次不归因 |
| VM 报错是闭包槽位缺失 | 实参插桩发现是原型上缺一个方法 | 报错位置不等于根因 |
| 换个包装入口能解决 | 多个入口的中间值逐字一致 | 不是入口问题 |
| 换一个传输客户端能解决 | 调用超时，且辅助函数有重试，实际次数未知 | 只能记为超时，不是拒绝 |
| 字段差异表很长，全补上就好 | 大部分差异 SDK 没读，或读到 undefined 是正常的 | 只处理有读值证据的项 |

## 可以带走的和带不走的

可以带走的是判断顺序：先定基线、分开来源、隔离时序、读值差异、诚实收口。对应 [问题路由](../references/problem-routing.md)、[对照实验](../references/controlled-experiments.md)、[签名来源隔离](../references/signature-source-isolation.md)、[原始 SDK 运行](../references/original-sdk-runtime.md)。

带不走的是具体结论：哪个头是闸门、需要哪些环境项、时效多长。这些在本案例内部三个端之间都不一样，换站点更不能套用。
