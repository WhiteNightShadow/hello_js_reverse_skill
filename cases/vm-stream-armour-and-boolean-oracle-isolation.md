# 等长字节码流式护甲与粗粒度布尔判决下的分层归因

> 难度：★★★★
> 还原方案：R1（编码层离线复现；会话透传字段取自同会话上游响应）
> 实现语言：Node.js / Python
> 最后验证日期：2026-11-13
> 平台类型：通用（已脱敏）
> 适用范围：授权测试目标上的双层脚本与时序交互校验接口；仅验证单目标同一时段连续请求
> 到达层级：S3（编码层离线往返一致 + 分层对照后业务链路连续通过）；未到 S4
> 失效条件：字节码脚本重新编译初态、外层信封改版，或服务端收紧时序统计校验

本案例已去掉站点、云厂商、域名、接口参数名、构建常量和单次样本的具体数值，只保留诊断链路、变量隔离顺序以及哪些初始假设被实验推翻。结论仅对当时的验证样本成立，不是全局规则。

## 背景

目标页面由外层调度脚本与按会话下发的字节码虚拟机脚本协同工作：初始化接口下发会话标识、动态脚本路径与交互题目参数；校验接口接收外层 Base64 编码的不透明载荷，HTTP 状态恒为 200，仅返回通过或拒绝的布尔字段，无细分错误码。内层明文在压缩编码后经一段虚拟机内的自修改状态查表变换，输出长度与压缩编码串严格相等。

## 问题定位记录

无细分错误码的布尔接口容易把不同层的失配混为一谈。按从外向内的顺序拆成四层后分别锁死：

| 层级 | 初始现象 | 实际问题层 | 处置方式 |
|---|---|---|---|
| 外层编码 | 解码后前几字节恒定，但全局搜不到魔数常量 | 不透明令牌（确定性流式变换） | 顺发包出口回溯字节码，同会话样本做往返闭环至 S2 |
| 动态配置 | 初始化响应下发每会话变化的脚本路径与配置项 | 疑似动态密钥干扰 | 对照同轮明文与密文，排除未参与变换的下发字段 |
| 单位标定 | 按页面几何直填的逻辑位移与内部记录不一致 | 渲染缩放与单位换算 | 用受控输入增量与脚本内部读数实测换算比 |
| 统计载荷 | 编码逐字节可逆、单位校准后仍持续返回布尔拒绝 | 时序载荷分布失配 | 冻结编码与单位层，对照当前目标真实交互采样的统计分布 |

```text
结论强度：编码层可逆【已证明】；排除浏览器物理事件源限制【已证明】；对齐当前目标实测基线分布的载荷组合充分性【已证明】（单项统计指标未做消融，不标必要条件）
未验证：会话透传子字段的跨会话离线独立生成、会话续期、跨天稳定性（S4）
```

## 走过的链路

1. **回溯固定前缀的来源**。多条密文外层解码后前几个字节完全固定，但静态搜索十进制、十六进制与字节数组均无果。改从发包出口向前追踪，定位到字节码中的等长自修改查表变换：由于初始状态在同一构建版本内固定，而压缩后的编码串开头字符恒定，变换输出的前几个字节自然恒定，并非源码硬编码魔数。
2. **同会话往返测试锁死编码层（S1 → S2）**。用同一会话抓到的真实输入与输出验证 `decode(encode(x)) == x` 逐字节一致，同时确认初始化下发的动态脚本路径字段并未进入该变换，排除了“每会话动态换密钥”的干扰假设。
3. **隔离观察环境与 UI 注入噪声**。排查过程中曾复用同一个持久化浏览器目录做自动化观察，导致设备遥测请求出现连接中断（`status 0`），误以为触发服务端封禁；改用每次全新的干净会话后恢复正常。同时发现当协议层已能离线构造载荷时，退回浏览器做 UI 事件拖动会同时引入容器 CSS 缩放、闭环修正抖动和环境状态污染，无法做单变量归因。
4. **实测标定单位换算**。对比外部输入位移与脚本采集到的内部序列终点，发现宿主容器存在非 1:1 的渲染缩放；通过受控增量实测校准换算比例后，固定几何终点变量。
5. **区分“物理事件源门禁”与“统计分布失配”**。在编码层逐字节正确、单位比例一致且由离线脚本直接提交的前提下：使用人工臆测的高密度平滑曲线连续被拒，而切换为对齐当前目标真实交互采样分布的序列后连续通过。这同时证明服务端在此样本上校验的是载荷统计形态，而非浏览器原生物理事件标记。
6. **诚实标注收口边界**。本次从平滑曲线切换到基线分布时同时调整了采样点数、时长与加减速阶段分布，因此结论只记“该分布组合充分性成立”，不将单一统计分位数写成通用必要条件；且载荷中一个同会话透传子字段仍取自初始化侧真实响应，故标记为带同会话前置依赖的 R1。

## 假设与纠偏

| 当时的假设 | 推翻它的证据 | 现在的结论 |
|---|---|---|
| 密文前几字节恒定，源码里一定有对应的魔数常量 | 固定初态流式变换吃进恒定压缩头自动算出该前缀 | 静态搜不到固定前缀时，先测改明文首字节是否改变前缀 |
| 初始化接口每轮变化的字段必然参与载荷加密 | 同构建版本下仅凭固定初态即可离线逐字节复现密文 | 动态下发字段未必进入变换，先用成对样本核对依赖边界 |
| 遥测接口返回 `status 0` 是服务端识别并封禁 | 去掉复用的脏浏览器目录、换干净会话后立即恢复 200 | 观察环境与验证环境分开，状态累积会伪装成风控拒绝 |
| 离线提交全拒说明必须走真实浏览器硬件级事件 | 同一离线提交链路换对齐真实基线分布的序列后连续通过 | 先固定编码层对比真实样本分布，不急于退回重型方案 |
| 采样点越密、曲线越平滑越容易通过 | 高密度平滑曲线全部被拒，贴合目标实测采样密度的序列通过 | 合成平滑曲线反而偏离真实采样分布，以目标实测基线为准 |
| 某目标测出的帧率、速度峰值位置与回拉幅度可跨站复用 | 宿主 CSS 缩放、指针设备刷新率与采集节流会直接改变分布 | 统计参数全部绑定具体目标与宿主布局，换目标重新采基线 |

## 可以带走的和带不走的

可以带走的是分层隔离顺序：面对仅返回布尔结果的黑盒接口，先离线用同会话样本把外层编码锁死到逐字节可逆，再校准渲染与协议单位比例，最后固定前两层、采集当前目标的真实基线样本做分布对照。通用判断见 [不透明令牌分析](../references/opaque-token-analysis.md)、[对照实验](../references/controlled-experiments.md)、[签名来源隔离](../references/signature-source-isolation.md) 与 [问题路由](../references/problem-routing.md)。

带不走的是任何具体数值与字段结构：置换表长度、初态常量、宿主容器缩放比、事件帧数区间、峰值速度所在进度百分比或末段回拉幅度。这些数值随 SDK 重编译、宿主页面 CSS 布局、高刷屏/触控采样率变化而变化，换目标甚至换同站其他宿主页面都不能硬编码照搬。

## 可验证事实清单

- [ ] 同一会话抓取的真实明文经本地编码器往返后是否逐字节一致（`decode(encode(x)) == x`）
- [ ] 修改输入首字节时，外层解码后的固定前缀字节是否随之改变
- [ ] 外部输入单位与脚本内部记录单位的换算比例是否已在当前宿主页面实测确认
- [ ] 观察用的浏览器目录是否每次独立清理，排除了跨轮本地存储污染
- [ ] 统计/时序序列是否基于当前目标采集的真实基线样本对照，而非跨站点套用经验阈值
