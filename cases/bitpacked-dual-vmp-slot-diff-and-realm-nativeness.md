# 位打包双分发器 JSVMP、定长槽位反解与沙箱原生性校准

> 难度：★★★★★
> 还原方案：R3（jsdom 运行原始 SDK；基于定长槽位反解与真实浏览器描述符快照做单点消融）
> 实现语言：Node.js / Python
> 最后验证日期：2026-11-17
> 平台类型：通用（已脱敏）
> 适用范围：授权测试目标上的挑战质询—令牌兑换—业务重放两段式接口；仅验证单目标当前 SDK 版本短批次
> 到达层级：S3（挑战兑换通过 + 业务接口返回目标数据）；未到 S4
> 失效条件：SDK 换版更新位置混淆常量表或槽位布局、新增环境探测块、出口网络策略或会话态门禁变化

本案例已去掉具体站点、域名、脚本文件名、接口路径、Cookie 参数名、业务返回码及单版本槽位常量，只保留测量污染排查、定长码点流逐槽消融顺序以及四类沙箱原生性探针的定位链路。结论仅对当时的验证样本成立，不是全局规则。

## 背景

目标业务接口在未持有有效挑战令牌时返回质询响应，下发动态脚本标识、挑战种子与服务端时间戳；客户端加载单行扁平化 JSVMP 脚本生成「固定短前缀 + Base64」形态的动态令牌，先提交至令牌兑换接口换取放行态，再重放原业务请求。

该脚本有两个显著结构特征：
1. **双分发循环与位打包状态号**：单文件内并存两个扁平化分发循环——主虚拟机将状态整数按移位与按位与拆成多段索引进入嵌套三层 `switch`（源码中搜不到明文 `case <状态号>`，跨函数调用通过 `apply(this, [stateId].concat(...))` 形态传递），而外层 IIFE 另有独立的次级分发循环。
2. **定长码点载荷与浮动编码长度**：SDK 收集环境特征后组装成「固定常量头 + 定长记录流」的码点序列，每个槽位按下标查小常量表做可逆加减/异或混淆，随后经 UTF-8 编码再转 Base64。由于码点跨过 `0x80` 边界会在单字节与多字节 UTF-8 间切换，两侧环境只要有少量槽位跨过该边界，最终 Base64 字符串长度就会浮动且尾部整体错位。

服务端同时存在三类不同层级的响应：正常下发挑战种子、已提交令牌但环境载荷自证未通过、以及出口网络前置拦截（连挑战种子都不下发）。

## 问题定位记录

本案例前半程的四次卡点均源于「测量手段本身改变了被测对象」，后半程则是 jsdom 原型链、特殊宿主对象与子 Realm 暴露了沙箱痕迹：

| 层级 | 初始现象 | 实际问题层 | 处置方式 |
|---|---|---|---|
| 出口网络 | 质询接口偶发不返回挑战种子 | 出口网络前置风控（IPv6 / 受限出口） | 在协议层先判定种子是否存在，未下发种子时不归因到令牌或沙箱 |
| 脚本取样 | 页面内重拉的脚本比归档版大数千字节，载荷数十槽不同 | 在线插桩改写路由跨导航残留 | 对照前查 `instrumentation(action="status")` 并 `stop`，只认 `len + sha256` 校验过的原始字节 |
| 基线采样 | 同一页面连续调用出值函数 3 次，步数与部分槽位每次都变 | 出值过程向 `window` 写键，污染后续 `Object.keys(window)` | 改为每次重载干净页面只调用一次，且不向主世界注入额外调试全局变量 |
| 时钟控制 | 将 `Date.now` / `performance.now` 冻成常数后执行步数暴涨 | 内部含依赖时钟推进的忙等校验循环 | 改为固定起点 + 每次读取受控单步递增，双侧在加载 SDK 前执行同一注入脚本 |

## 走过的链路

1. **先核对脚本字节身份，排除在线改写残留**。初期在浏览器开启 `instrumentation(action="install")` 观察分支后未显式 `stop`，后续导航与取样持续命中改写路由，导致取回的脚本体积变大、产出的令牌数十个槽位偏移，一度误判为“服务端按流量下发了第二版 SDK”。停掉活动改写并核对归档原版 `len + sha256` 后，双版本假象消失。
2. **固定单次干净采样与单调推进时钟**。在干净页面「重载 → 单次调用」采多组浏览器基线样本，确认此前“浏览器每次结果都不同”是同页重复调用向 `window` 挂键以及调试辅助全局变量改变了 `Object.keys(window).length` 所致；同时将双侧随机源与单调推进时钟用同一段前置脚本固定在 SDK 加载之前。
3. **逆向解包到槽位层，先分类再消融**。不直接对浮动长度的 Base64 字符串做字符级 diff，而是顺发包前编码循环逆推出逐位置可逆解码函数，将浏览器与本地令牌双双还原为定长码点槽位流：
   - 先用浏览器侧多组独立重载样本做 A/A 交集，标出每次自身都在变的时间戳与全局键数派生槽，不把自抖动槽当作环境缺口；
   - 再针对「浏览器侧恒定、但与本地 jsdom 不同」的槽位逐一改单个环境量，要求每次修复只翻转目标槽而不引起大面积级联变化。
4. **挂对主分发循环并控制高频探针开销**。首次在分发器末尾 `catch` 挂 `finally` 追踪激活帧时，几百次状态跳转只记录到一次退出——排查发现单行脚本内有两个扁平化循环，文件末尾的 `catch` 属于外层次级循环，切回主虚拟机的位打包分发循环（或使用 `instrumentation(..., tap_stage_calls=True)` / `action="rewrite_source"` 做离线阶段对照，见 [源码级插桩指南](../references/jsvmp-source-instrumentation.md)）后才准确拿到各探针所在的调用栈。同时实测发现对热寄存器“每次变化都调外部 JS 回调”会直接令产出的令牌变形，改为内联整数计数器 + 目标步数窗口门控后消除探针自伤。
5. **按单点消融逐一补齐沙箱原生性缺口**：
   - **文档对象形状与构造器存在性**：SDK 同时采集 `Object.getOwnPropertyNames(document).length`、`Object.keys(document).length`，并探测一批全局构造器是否存在（`window[name] !== undefined`）。一方面，手写补丁若将 `readyState`、`visibilityState`、`fonts` 等原型属性直接挂在 `document` 实例上会抬高自有属性计数，需通过 `evaluate_js(..., world="main")` 采集真实页面的自有/原型描述符快照并把原型属性挂回 `Document.prototype`；另一方面，对真实基线浏览器不存在的全局构造器保持 `undefined`，避免空壳存根诱导 SDK 进入深层实例校验分支。
   - **`document.all` 引擎级活性与不可删索引**：仅用 `%GetUndetectable()`（Node 需 `--allow-natives-syntax`）加动态 `length` 仍不够——探针不仅实时读取新增节点下标，还会执行 `delete document.all[i]` 后复读；将 `all` 定义在 `Document.prototype` 上，并用原型 `Proxy` 配合有效下标 `0..len-1` 的 `configurable: false` 同步后通过校验。
   - **同源 `iframe` 子 Realm 构造器与原型链**：SDK 创建临时 `iframe` 并读取 `String(iframe.contentWindow.constructor)` 的长度入槽。由于每个 `iframe` 拥有独立 `Function.prototype`，且 jsdom 中 `childWin.constructor` 原型链默认指向 Node 外层 `Function.prototype`，仅覆写顶层 `window.Function.prototype.toString` 完全不生效；改为同时拦截 `HTMLIFrameElement.prototype` 的 `contentWindow` 与 `contentDocument` getter，将 `childWin.EventTarget` 归位到子 Realm `Function.prototype` 并对子窗口构造器与原型链递归标记后对齐。
   - **Canvas 渲染摘要与窗口几何**：几何尺寸与 `canvas.toDataURL()` 均取自同一基线浏览器的实测快照（摘要按字符拆入连续槽位），不在本地手写默认值或沿用旧设备快照。
6. **服务端闭环验收**。每次修改先在离线槽位对比确认稳定槽全部一致、ASCII 码点计数一致，再执行挑战兑换与业务重放；同时在客户端区分“未下发种子的出口网络拦截”与“携带种子兑换失败的载荷拒绝”，避免网络层限流时误改沙箱补丁。

## 假设与纠偏

| 当时的假设 | 推翻它的证据 | 现在的结论 |
|---|---|---|
| 服务端随机下发两个不同体积的 SDK 版本 | `instrumentation(action="status")` 显示改写路由仍处于激活态；`stop` 后拉取字节与原版 `sha256` 完全一致 | 做任何字节归档或载荷对照前先清查并关闭在线改写路由 |
| 浏览器侧同页连算三次都不一样，说明载荷不可复现 | 改为每次重载干净页面只算一次后，除时间槽外其余槽位跨次恒定 | 出值函数自身可能改写全局键集或内部状态，基线采样坚持单次加载单次调用 |
| 直接对比两条最终 Base64 令牌即可看出差异段 | 单个码点跨过 `0x80` 改变 UTF-8 字节数后，后续 Base64 字符全部错位 | 只要存在可逆外层编码或逐槽掩码，先反解成定长槽位流再逐槽比较 |
| 可以换到 `robots.txt` 等极简静态页采样来稳定基准 | 换页面改变了 DOM 节点数、URL 与文档属性集，头部与多处环境槽整体跳变 | 基准必须在真实目标页面环境下采集，换页面等于更换被测输入 |
| 在顶层 `window` 覆写 `Function.prototype.toString` 即可覆盖所有函数检测 | 目标槽位毫无变化，`iframe.contentWindow.Function.prototype !== window.Function.prototype` | 涉及 `iframe` 探测时，在 `contentWindow` 访问入口对子 Realm 单独修补 |
| 冻死 `Date.now` 最利于双侧确定性对齐 | 完全恒定的时间戳触发内部忙等检测分支，步数从十余万膨胀至百万级 | 存在忙等循环时使用“固定初值 + 单步微小递增”替代恒定死值 |

## 可以带走的和带不走的

可以带走的是两条通用纪律与四类沙箱原生性检查点：
1. **先证测量无污染，再做残差归因**：核对在线改写路由状态与原始脚本 `sha256`、避免调试全局变量与同页连调污染键数、先反解槽位流并用同侧 A/A 过滤自抖动槽，详见 [浏览器取证契约](../references/browser-evidence-contract.md) 与 [对照实验](../references/controlled-experiments.md)。
2. **补环境不只看键值，还要看原型归属、引擎特殊对象与子 Realm 边界**：`document` 实例/原型描述符归属、`document.all` 的 `%GetUndetectable()` 不可删活索引、`iframe.contentWindow` 子 Realm 独立 `toString` 以及单调时钟推进，通用代码模式与边界见 [原始 SDK 运行](../references/original-sdk-runtime.md) 与 [jsdom 环境补丁](../references/jsdom-env-patches.md)。

带不走的是任何绑定单版本或单站点的常数：总码点数、常量头长度、位置混淆表数值、时区换算式、特定 `document` 属性白名单、固定窗口尺寸或他处采集的 Canvas 摘要。SDK 换版时槽位可能整体平移或增删功能块（如新增 WebGL 探测段），必须重新校验脚本 `sha256`、重采同机浏览器快照并重跑槽位残差对比。
