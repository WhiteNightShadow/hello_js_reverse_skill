# 任务级检查与失效重查

检查的目的是选对执行路径、复用可靠证据，避免每个工具调用前重复扫描、误清理或无关阻塞。

## 首次进入任务

| 任务类型 | 必须确认 | 可直接跳过 |
|---|---|---|
| 修复已有代码、离线验签、读取已有抓包 | 当前工作目录、已有代码/样本、对应运行时 | 浏览器启动、自定义浏览器检查、与任务无关的 cases 全库扫描 |
| 普通 JSON API 采集 | 鉴权来源、业务成功条件、分页/结束规则、输出/恢复约定 | JS 逆向流程、Hook、原生 trace |
| 浏览器签名分析或资源取证 | check_environment、目标页/Frame、现有 Hook/捕获属于哪个任务 | 无理由的 reset、每次点击前的完整环境检查 |
| 已有任务续做/目标改版 | 上次目标和证据、manifest/SDK/签名代码变化 | 已有清晰结论的重复需求确认 |

需要浏览器时首次调用 `check_environment()`。MCP v1.7 起 initialize.serverInfo.version 与工具的 mcp.version 都表示应用版本；旧版 initialize 可能显示 SDK 版本，不能直接当作工具能力版本。只根据当前任务需要的能力判断是否可继续：旧 `overall_ok` 仍是浏览器环境总览；缺少浏览器不阻止 `runtime="node"` 或本地协议任务。`task_readiness` 是分项提示，不保证运行时请求一定成功。

若已有状态，先识别是否是同一任务。`has_residuals=true` 可能意味着当前有效的 Hook 或捕获，不是清理指令；不得据此自动 reset。`review.state_fingerprint` 是浏览器实例/页面/已注册脚本等的范围提示，不包含完整 Cookie、SDK 与页面内部状态，不能据此宣称环境完全未变。

长任务在现有工作日志记录目标、当前模式、浏览器 instance_id、SDK/签名基线和有效证据即可，不需要每调用一次工具就生成检查文件。

## 何时重查、查什么

| 观察到的变化 | 最小复查 |
|---|---|
| 同任务连续点击/翻页/抓样本，未见相关异常 | 读取当前调用结果；复用首检，不再次 check_environment |
| 浏览器重启、断连、重新 attach | check_environment + get_page_info，旧 Frame/请求 ID 与上下文不能默认复用 |
| 导航或 Frame 变化 | get_page_info 与目标选择器；仅 Frame 变化不必重新扫描全部 Python 依赖 |
| 登录态改变、401/403 或业务拒绝 | 当前 Cookie/鉴权与成功样本；避免先清全部 Cookie |
| SDK/签名代码或需求配置改版 | manifest 差异 + 当前样本；只重新分析受影响部分 |
| 准备发在线请求 | 按 [在线门禁](controlled-experiments.md#在线门禁) 检查版本、凭据余量、值是否未用过 |
| 页面实际加载的 SDK 与本地不同 | 先同步并记录版本，再发请求；已发的不算候选失败 |
| Hook/trace 策略变化 | 返回值、pending/实际 trace、卸载边界；不是默认重启所有浏览器 |
| 错误页快照超时 | 使用 get_page_info 和已捕获的 document failure 定位；take_snapshot 有独立超时，不反复等待相同错误页 |
| 抓包丢弃、pending、正文失败或截断 | network_capture(status) / 具体请求详情；必要时有意重采当前样本 |
| 长输入没有进入工具调用日志、终端回显中途停止 | 检查客户端/PTY 传输，改用结构化 SDK 参数或文件化脚本；不要误判浏览器表达式失败并重放请求 |
| 工具参数错误/不支持参数 | 查当前工具 schema，修正调用；无关环境扫描无助于解决参数错误 |
| 调用失败且可能已产生页面/服务端副作用 | 先核对当前状态，不自动换通道或重放非幂等请求 |

如果续做时上下文不足，先读取保存的任务日志和真实状态；不要把“忘记上次检查结果”变成无限循环审查，也不要跳过关键验证后假定成功。

跨导航保存对比样本时，明确传 `navigate(..., clear_network_capture=False)`；默认导航可能清理旧采集。先保存必要产物再执行 clear/reset/close。

点击/输入后可能还有异步签名、微任务或防抖。停止捕获前，用业务完成元素、页面状态或新的请求ID确认目标请求已发出；stop 的等待只处理已捕获请求。无法确认时记录不完整，不能把“缓冲区为空”当作没有请求，也不要盲目重放操作。
