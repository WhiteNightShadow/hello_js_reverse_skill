# 常见误判与处理

遇到对应问题时读取；无需为每个任务重复背诵清单。

| 误判或反模式 | 应执行的检查 |
|---|---|
| 看到 HTTP 200 空内容就断定签名或环境错误 | 检查业务错误码、参数、权限、分页结束条件及同期成功样本 |
| 超时或 SSL 错误就断定 TLS 指纹被识别 | 区分网络、代理、证书、协议与服务端故障，做受控对比 |
| 本地失败、浏览器成功就断定 TLS | 先排除已用值、会话到期和请求形态，再做传输对照 |
| 结构合法、校验位正确就认为值可用 | 这只到 S1，服务端是否接受要在线判断 |
| 控制组失败时仍记“候选失败” | 控制组失效的批次没有归因价值，恢复基线后重做 |
| 报告写“只改了 X”但没核对实际发包 | 用实际请求回读，随机字段、复用字段、客户端改写都可能混入 |
| 把未发送、超时、拒绝合并成“失败” | 分类记录，超时和未发送都不是服务端拒绝 |
| 实验跨过凭据到期点仍归因到候选 | 发送前检查余量，跨过到期点的结果无效 |
| 一端需要某个头就给所有端都加 | 按接口单独验证，多发也可能被拒 |
| 历史“可选”“可重放”的结论直接沿用 | 结论带日期和接口，服务端可在 SDK 不变时收紧 |
| 环境差异表列得很长就全部补上 | 先分清观察差异、SDK 实读、服务端校验，只处理有读值证据的项 |
| SDK 读到 undefined 就当缺口 | 真实浏览器也是 undefined 的探测项保持未定义 |
| 初始化之后再改 Cookie 或 Storage | SDK 可能首次读取后缓存，用哨兵实验确认，先 seed 后 init |
| 一次改多项后成功，归因到其中一项 | 这只证明组合成立，单项归因需要消融 |
| 请求头里的版本当成 SDK 版本 | 分开记录文件哈希、公开版本、请求头版本、协议标记和实现修订 |
| 用“唯一”“必须”“硬墙”写结论 | 换成带接口、版本、日期和强度的观察，这类词最容易过期 |
| 改了一项没变化，就认定这项无关 | 可能两道闸门并联，用交叉矩阵确认 |
| 单次拒绝或单次成功就下结论 | 结果时好时坏时开稳定性批次，报成功数和翻转数 |
| 工具没看到差异，就认定没有差异 | 先做 A/A 和阳性对照，确认工具有分辨力 |
| 把随时钟变化的差异当环境问题 | 隔几分钟重采一侧再比，差异跟着时间走就不是环境 |
| 首个值有效、之后全空且无异常 | 可能是定时器或自检逻辑没跑，用真实定时器并等待后复测 |
| 结果合理但每次不同，当成采集成功 | 可能是假数据，比较跨运行是否一致 |
| 结果跨运行稳定，就认定数据是真的 | 失效会话也可能稳定返回错误数据，采集前后各查一次身份接口 |
| 过期令牌的 403 被读成环境检测 | 先读响应正文和业务码 |
| 把算好的中间值喂给实现，比对通过就算还原 | 派生值只能作调试断言，实现只收原始输入 |
| 用过期 Cookie 硬编码支撑可持续采集 | 为鉴权/动态 Cookie 定义刷新来源、失败条件和恢复方式 |
| 拿浏览器验签通过证明协议程序可独立运行 | 用 Node runtime 或实际 Python 产物在无浏览器环境回归 |
| 样本为空、expected 缺失或字段名拼错仍当通过 | 验证输入结构，每个样本至少一个有效断言 |
| 已有同站项目却从零创建替代项目 | 先读需求工作区、基线和相关 cases，再判断改版范围 |
| Hook 已注册/pending 就认定捕获成功 | 检查同 world/Frame 的 get_trace_data；未命中不构成未执行证据 |
| 源码改写成功就认定插桩运行 | 检查 runtime 标记和实际日志，再判断解析/执行失败 |
| 原生 trace 没记录就认定没读取属性 | 核对固定点覆盖、事件 cap、进程 acknowledgement 和快照语义 |
| 同 URL 多请求靠 URL 猜响应归属 | 使用 MCP v1.6.0 的请求对象关联；调用栈归因仍可能是启发式 |
| stop 立即返回就认定所有响应完整 | 指定 wait_timeout_ms 并检查 pending_requests/pending_responses/body_state |
| 将 buffer/正文截断当完整证据 | 检查 dropped_requests、body_state 和两层 truncated 字段 |
| 请求超时后无条件重放 POST | 无法证明幂等时停止并核对服务端结果，显式配置才重试 |
| 接口返回业务错误却用空列表标为采集完成 | 先验证业务状态和数据结构，成功后再推进 checkpoint |

默认失败处理：回看已有证据和 cases → 按 [问题路由](problem-routing.md) 定层 → 用对照实验排除假设 → 校验入口与输入输出 → 按证据调整最小环境 → 记录未解决问题。不要调用已移除的 Session/Assertion 工具，不要用强制停顿代替诊断。

验收分层：离线 fixture 回归、当前接口至少 5 次代表性请求、按业务需要追加长时间测试。没有实际跑过的时长不能写成通过。浏览器依赖是否允许以用户的交付要求为准，默认协议模式保持无浏览器依赖。
