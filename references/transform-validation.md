# 改写候选的行为验证

仅在反混淆、字符串解码、常量折叠、控制流简化或插桩时读取。AST 能定位语法结构，不自动保证改写后行为等价。

## 分级判定

改写结果按四级判定，只有行为通过才算成功：

1. 能解析。
2. 行为相同：原文件和改写文件过同一组 fixture 或 harness，比较结果有没有变动。
3. 简化了多少。
4. 是否可读。

简化程度和相似度都不能代替第二级。能解析但行为变了是最隐蔽的失败，公开评测把这种情况叫 semantic manipulation（[JsDeObsBench](https://github.com/Ch3nYe/JsDeObsBench)）。

- 快照测试只说明输出没变，不说明语义等价。自写规则用语义语料回归，接受结果变动要有人审（思路见 [wakaru 的 Test262 回归](https://github.com/pionxzh/wakaru/blob/main/docs/test262-roundtrip.md)）。
- 改写分两类：不求值的和要求值的。后者放隔离环境执行，每条规则带正例和负例。
- 带自防护或多层变换的代码，工具大概率失效，优先运行原始代码。
- LLM 反混淆的结果一律按候选处理。

## 改写前后保留哪些证据

- 原脚本、候选脚本、各自 SHA-256 与 diff 分开保存，避免覆盖唯一原样本。
- 先为目标签名/输出采集明确输入，包含时间、随机数、URL 原文与 Body 原文；环境依赖保持一致。
- 一次改变一个有解释的规则，先用当前 fixture 比较返回值、类型和异常，再用实际业务请求确认。
- 多个 fixture 通过仅说明这些样本一致，不是全程序等价证明。只有“可阅读”的解码视图要标为分析副本，不能直接替换生产签名逻辑。

## 必查的反例类型

| 改写 | 需要保留的语义 |
|---|---|
| 常量折叠 | 双精度浮点、负零、NaN/Infinity、字符串拼接与隐式类型转换；不能为好看截短小数 |
| 按函数名替换调用 | 检查词法绑定，局部 atob/parseInt 等可能遮蔽全局同名函数 |
| 自动解码 Base64/hex 字面量 | 编码字符串可能是实际业务输入；优先增加注释/候选视图，不直接替换其值 |
| 删除永假分支 | 保留 var 声明提升、块作用域和异常时机 |
| 重写成员访问/函数调用 | 保留 this、getter/副作用次数、求值顺序、可选链与异常行为 |
| 打印 trace | 区分原函数执行与序列化参数引发的 getter/toString 副作用 |

## 使用当前工具验证

对独立函数，从原脚本的真实执行结果构造非空 `expected`，再用 `verify_signer_offline(..., runtime="node")` 检查候选；与 DOM/SDK 绑定的代码在需求项目同一环境中分别运行。不要重新生成期望值来迎合候选输出。

当目标是取证和补环境时，优先保存实际响应字节、读取少量源码与追踪真实输入输出。不要因为另一个 MCP 有“自动解混淆”按钮就把未经验证的改写作为默认步骤。
